## О проекте

RPG Adventure — браузерная ролевая игра с боевой системой, исследованием регионов, развитием персонажа и долгой кампанией. Игра запускается как Telegram Mini App и в обычном браузере.

**Главное правило разработки:** версия 1.0 завершается по зафиксированному ТЗ. Новые функции не добавляются без одобренного [Change Request](docs/CHANGE_REQUEST_TEMPLATE.md).

## Кампания 1.0

| Регион | Этапы | Роль |
|---|---:|---|
| Деревня | — | Безопасный центр |
| Лес | 30 | Стартовая область |
| Горы | 40 | Второй регион |
| Руины | 50 | Третий регион |
| Логово дракона | 60 | Финальная область |

Всего — **180 боевых этапов**. Финальное сражение проходит на 60-м этапе Логова дракона: противник — **Пожиратель миров** (`world_eater`). Победа открывает концовку и Новую игру+.

Цель кампании — 30+ часов. Это критерий приёмки, а не подтверждённая продолжительность: хронометраж ещё предстоит проверить полноценными прохождениями.

## Игровые системы

- **Три класса:** Воин, Маг и Лучник — с отдельными боевыми навыками.
- **Тактические сражения:** фазы боссов, намерения противников, эффекты состояний, стихийные уязвимости и сопротивления.
- **Развитие героя:** уровни, таланты, экипировка, заточка, руны и реликвии.
- **Исследование:** регионы, подземелья, события, секретные комнаты и контрольные точки.
- **Прогресс:** квесты, достижения, коллекция предметов и региональные награды.
- **Новая игра+:** перенос долгосрочного прогресса и повторное прохождение кампании.

## Запуск и тесты

Требуется **Node.js 20 или новее**. Сторонние npm-зависимости для тестового набора не нужны.

```bash
# Установить проект не требуется — зависимости отсутствуют.
npm test
```

Для локального запуска игры:

```bash
python -m http.server 8000
```

Затем открой `http://localhost:8000`.

GitHub Actions запускает `npm test` при push и pull request. Результат автоматических тестов не заменяет ручную проверку браузера и Telegram WebView.

## Сохранения и ограничения

Прогресс хранится локально в `localStorage` текущего браузера. Автоматической синхронизации между устройствами и браузерами нет. Формат сохранений версионируется; предусмотрены миграции и recovery-копия для защиты от повреждённых или неподдерживаемых данных.

## Правила вклада и изменений

1. Сверяй каждую задачу с [PROJECT_SPEC](docs/PROJECT_SPEC.md).
2. Не расширяй scope 1.0 без согласованного Change Request.
3. Игровые правила размещай в `js/systems`, данные — в `js/data`, отображение — в `js/ui`.
4. Изменения формата сохранений сопровождай последовательной миграцией и тестом старого профиля.
5. Перед завершением задачи запускай `npm test` и фиксируй результат в [ROADMAP](ROADMAP.md).
